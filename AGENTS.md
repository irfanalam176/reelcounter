## Commands / repo
- Package is `reelcount` (`package:reelcount/...`) but source folder is `reelcounter`; Android namespace/applicationId and channel prefix stay `com.reelcount.app`. Dart SDK `^3.12.2`; Android JVM/Java 17, AGP 9.0.1, Kotlin Android 2.3.20.
- `README.md` is the untouched Flutter template. No CI, custom task runner, codegen, or repo-local OpenCode config; trust `pubspec.yaml`, Gradle, and source.
- From repo root: `flutter pub get` after pubspec changes, then `flutter analyze` (lint + typecheck), `flutter test --no-pub`, `flutter build apk --release`. No separate lint/typecheck script.
- Plain `flutter test` can fail deleting `ios/Flutter/ephemeral/Packages/.packages`; `--no-pub` passes. Focused: `flutter test --no-pub <file> --plain-name "<name>"`: `floating_bubble_service_test.dart` / `recordWatchedVideo`, `history and reminder methods`; `widget_test.dart` / `background setting shortcuts open system settings`, `daily target drives progress`, `bottom navigation opens insights, history, and settings`, `setup statuses refresh after returning from settings`, `setup and permissions reopens the permissions screen after completion`; `onboarding_flow_test.dart` / `all permissions appear on one screen`, `every grant button opens the correct settings`, `restricted settings stays an advanced confirmation requirement`, `final check identifies incomplete settings without marking them granted`, `reopening after completed setup opens permissions instead of success`; `bubble_status_test.dart` / `tracking requires an active detector and a visible bubble`.
- Do not reintroduce stale wizard assertions (`Start Setup`, `STEP 1 OF 7`, `Continue`, `Tap the three-dot menu`, `Have you completed all these configurations?`).
- Gradle redirects output to repo-root `build/`; debug install: `flutter build apk --debug`, then `adb install -r build\app\outputs\flutter-apk\app-debug.apk`. Release APK uses debug `signingConfig`; do not call it production-signed.

## App wiring / UI state
- `lib/main.dart` accepts optional service/storage; storage defaults to `SharedPreferencesOnboardingStorage`, service defaults downstream; gate is `onboarding_completed`; storage-load failure shows retry. If service is null, `HomeScreen` and `OnboardingScreen` each build their own `FloatingBubbleService()`; inject one in `ReelCountApp` to share. Dark theme uses bundled Inter font.
- Brand is Scrollo. `HomeScreen` is bottom-nav Home/Insights/History/Settings, full-refreshes on init/resume, but its event listener mirrors only counter/status; `_safeHistory`/`_safeReminder` swallow errors. Dashboard shows only the first setup issue from overlay/background/autoStart/pauseApp/accessibility; `restrictedSettings` appears via `Setup & Permissions`.
- Onboarding keys `onboarding_completed`, `onboarding_step`, `onboarding_confirmed_steps` are Dart prefs, separate from native `reelcounter_bubble`. Seven steps (notifications, overlay, background, autoStart, pauseApp, restrictedSettings, accessibility) render together in one scrollable dashboard; enum also has confirmation/success. Notifications required; autoStart/restrictedSettings and background/pauseApp with `unknown` status are confirmation-gated.
- Saved `success` renders success only while onboarding is incomplete; `startAtConfirmation`/`Setup & Permissions` force the dashboard even from saved `success`, refresh on resume/return, and scroll to the first ungranted card on open.
- `restrictedSettings` is user-confirmed: `Settings → Apps → Scrollo → Three-dot menu → Allow restricted settings`, with `On some devices this is under Advanced settings.`; "Open App Info Settings" reuses `requestPauseAppActivity()` (no dedicated intent). "Open Accessibility Settings" calls `requestAccessibilityPermission()` directly.
- Insights uses `history.take(7)`; native history is ascending with the current day appended last, so "Last 7 days" shows the oldest 7 archived days once more than 7 exist.

## Bridge / events / persistence
- Sole Dart bridge is `lib/services/floating_bubble_service.dart`; native detection writes directly via `ReelDetectionAccessibilityService` -> `VideoCounterManager` -> `BubblePreferences`, then notifies the channel. `recordWatchedVideo()` is a manual/test surface, not the production path.
- Fixed channels `com.reelcount.app/floating_bubble` and `com.reelcount.app/floating_bubble_events`; keep Dart `FloatingBubbleMethod`/`FloatingBubbleEventName`, Kotlin `FloatingBubbleChannel.Method`/`Event`, and tests in sync. No `updateCounter`/`incrementCounter`/`decrementCounter`. Dart enum lookup throws `StateError`; native `notImplemented()` surfaces as `FloatingBubbleException('CHANNEL_UNAVAILABLE')`; malformed payloads throw `FormatException`.
- Status payload has current `detectionState/detectionMessage` plus legacy `trackingState/trackingMessage`, `trackingEngineConnected`, `trackingActive`; keep `BubbleStatus.fromMap` aliases. Native computes `accessibilityServiceRunning` and `trackingEngineConnected` separately; Dart aliases one getter. `bubbleVisible` requires overlay permission + running service + persisted `bubble_active`; `expanded` requires visible; `trackingActive` requires detection `active` + visible.
- `sendEvent()` drops consecutive identical type+status signatures; signature includes detection states, counter fields, bubble/status fields, and `trackingEngineConnected`, but omits target, `trackingActive`, and `trackingMessage`. Target changes and reset still emit `counterChanged`; `onHostResumed()` emits only overlay/accessibility changes from attach-time baselines.
- No manual `+1`/`-1`; reset is bulk and confirmation-gated. Native `resetCounts()` clears current-day counters only (history and `processed_event_ids` untouched), despite settings copy claiming history is cleared. Expanded bubble only has Collapse/Hide.
- Counters, `daily_target`, `daily_history`, and reminder/notification-preference keys live in native prefs `reelcounter_bubble`; target defaults `50`, clamped `>= 0`. History caps at 365 ascending entries, injects the current day live, and does not archive zero-count prior days. Lazy rollover archives nonzero prior-day counts, clears counters, `counter_total`, and `processed_event_ids`, but leaves bubble positions; stable IDs can recur unless still in `recentKeys`.
- Daily reminders use native `AlarmManager` + `DailyReminderReceiver`/`DailyReminderBootReceiver`, request `POST_NOTIFICATIONS` through the bridge, and never change Android settings programmatically; copy must tell users to open Scrollo before scrolling. Prompt is one-shot via `notification_permission_requested`; later denial needs `openNotificationSettings`; `requestNotificationPermission()` returns false immediately after launching the prompt and does not deliver the result back to Dart — re-read status.
- Daily limit milestones are native-only in `DailyLimitNotifier`, fired after `recordWatchedVideo()` for 50/90/100 when target/count > 0 and notification permission is present; sounding channel `reelcount_daily_limit_milestones_sound`. Date-prefixed markers in `limit_milestones_notified` enforce once/day and clear on reset/rollover; one record crossing multiple thresholds can fire multiple. No Dart method/event and no other percentage milestones.

## Android lifecycle / permissions
- Overlay needs `SYSTEM_ALERT_WINDOW` + Android 8/O runtime checks. Keep `foregroundServiceType="specialUse"`, subtype `floating_bubble_counter`, FGS permissions, and checks. `dispatch()` no-ops unless the service runs (except `start()` via `startForegroundService()`), so `refreshCounter()` drops updates while stopped; AppOps revocation and `onTaskRemoved()` (`stopWithTask="true"`) tear the bubble down. Restore only when `canDraw` and persisted `bubble_active`.
- `VideoCounterManager.appTaskActive` is in-memory, starts `false`, and is set by `MainActivity`/`ScrolloTaskMonitorService`; persisted `app_task_active` is unused. Monitor is `START_NOT_STICKY`, so process death/swipe-away stops counting until app reopen; detection errors stay hidden as `stopped` while the gate is false.
- Overlay brain icon uses the same 50/90/100 cutoffs as milestones: green below 50%, yellow at 50%, orange at 90%, red at 100%+; `dailyTarget <= 0` stays green. `FloatingBubbleView.setCount()` re-reads target and recolors on refresh/reset.
- Accessibility permission means the component is in `ENABLED_ACCESSIBILITY_SERVICES`, not global `ACCESSIBILITY_ENABLED`; `accessibilityServiceRunning` is in-memory `isConnected`, distinct from permission and `trackingEngineConnected`. Keep delayed `runDetect()` cancellable, serialized, and guarded (overlaps are dropped); route failures through `reportError()`. Preserve config flags (`flagReportViewIds|flagIncludeNotImportantViews|flagRetrieveInteractiveWindows`), `canRetrieveWindowContent=true`, and window/content/click/scroll events; XML `notificationTimeout="200"` is framework coalescing, app debounce is ~500ms for window/content/click and 0ms for scroll.
- Background Activity: `allowed|restricted|unknown` from PowerManager Doze whitelist; request order is ignore-battery -> battery-optimization list -> app details. Auto Background Start is action-only (no status query): try resolved brand-specific OEM components, then app details/apps list; add new OEM packages to manifest `<queries>`. Pause App Activity If Unused: API 30+ `isAutoRevokeWhitelisted` maps to `disabled|enabled|unknown`; request only opens settings. Never change these settings programmatically.

## Detection / identity
- Supported packages: Instagram (`com.instagram.android`, `com.instagram.barcelona`), YouTube/YouTube Music, Facebook (`katana`, `android`, `lite`), exact TikTok `com.zhiliaoapp.musically` plus `com.tiktok.` prefix, Snapchat; unsupported/package-less events ignored. `sessionNonce` regenerates on every service connection.
- For YouTube/Instagram/Facebook, scroll transitions bypass the `sessionActive || lastKey != null` gate and cancel pending ~500ms detects. Threshold is 60 generally, 1 for YouTube/Instagram with `effectiveMagnitude=1` fallback; threshold rejects log `SCROLL_TRANSITION_IGNORED reason=threshold`. Only positive/down scrolls count; negative motion returns `UP` and cancels pending (`SCROLL_TRANSITION_CANCELLED direction=up`) — `next`/`previous` labels are log-only. Repeated downs while pending coalesce; cooldown is checked after threshold/coalescing (500ms generally, 100ms Instagram) and starts only after an accepted `newByTransition`. `scheduleDetect(fromScrollEvent: true)` blocks initial-detection counting.
- Viewer detection is BFS over `AccessibilityNodeInfo` (main max 1500 nodes/depth 20; hint/media/identity sub-searches 200/400/400) and picks the largest eligible area. Direct viewer branches allow non-scrollable Snapchat (`opera_viewer`/`spotlight_container`), YouTube, Instagram, and Facebook; generic media gate 0.3x0.2, dominant 0.5x0.5, FB letterbox 0.8x0.3. Text hints gate `allowed` for YouTube/Instagram/Facebook when no idHint; `feedGuard` rejects feed-like nodes when no hint and >3 media-like nodes.
- Prefer author/caption identity: captions/author-field tokens must pass `stableToken` (lowercase, strip digits/whitespace, length 2..140, no social-stat/generic tokens); regex authors bypass that filter and cap at 48. Structural fallback uses <=8 sorted tokens plus class/id/childCount/coarse bounds. Stable `eventId` is `baseKey`; unstable IDs add `sessionNonce#transitionEpoch`; `recentKeys` (32) plus native `processed_event_ids` suppress revisits.
- `COUNTER_UPDATED` is logged inside `recordWatchedVideo()` and can precede `REEL_RECORDED`; only native processed-event duplicates log `REEL_RECORDED duplicate=true` without `COUNTER_UPDATED`, while detector-side revisits return earlier. `BUBBLE_UPDATED` is not guaranteed if the bubble service is stopped. `TREE`/`SCROLLABLE` dumps happen only on `no-viewer-node`, rate-limited ~3s/platform; `no-root-window` emits no dump.

## Testing / on-device
- No native unit/instrumented tests; detector/scroll changes need on-device log verification. Channel tests mock `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`; event tests use `MockStreamHandler`; widget tests inject storage and assert no `+1`/`-1`, reset confirmation, and independent statuses; `onboarding_flow_test.dart` asserts the single-screen dashboard. `widget_test.dart`'s `EventEmittingService` bypasses the mock messenger by overriding methods directly.
- Open Scrollo/start bubble, then the target app: events are silently dropped before `ACCESSIBILITY_EVENT_RECEIVED` while `appTaskActive` is false, package blank, or platform unsupported.
- Single device: `adb logcat -c`, then `adb logcat -s ReelDetection VideoCounterManager BubbleUpdate`; add `AccessibilityManagerService AndroidRuntime ActivityManager` for lifecycle. Multiple devices: `adb devices`, then `adb -s <serial> logcat -c` / `adb -s <serial> logcat -s ...` (`-s` before `logcat` selects device; after `logcat` is tag filter).
- Success trace: `SERVICE_CONNECTED` -> `APP_FOREGROUND` -> `ACCESSIBILITY_EVENT_RECEIVED` -> `SCROLL_TRANSITION*` -> `VIEWER_DETECTED` -> `VIDEO_CONTENT_IDENTIFIED` -> `DUPLICATE_CHECK` -> `COUNTER_UPDATED` -> `REEL_RECORDED` -> `BUBBLE_UPDATED` (last only while bubble service runs). Diagnostics: `no-root-window` has no dump; `no-viewer-node` has rate-limited `TREE*`/`SCROLLABLE*`; milestone failures log under `VideoCounterManager`.
- `adb -s <serial> shell dumpsys accessibility` distinguishes bound from crashed service; `adb -s <serial> shell uiautomator dump /sdcard/window.xml` then `cat /sdcard/window.xml` is the reference for viewer nodes.
