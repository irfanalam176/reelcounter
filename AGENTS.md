# AGENTS.md

## Commands / facts
- Flutter package is `reelcount` (`package:reelcount/...`) but the source folder is `reelcounter`; Android namespace/applicationId and channel prefix stay `com.reelcount.app`. Dart SDK is `^3.12.2`.
- `README.md` is the untouched Flutter template; there is no CI, custom task runner, codegen config, or repo-local OpenCode config. Trust `pubspec.yaml`, Gradle, and source.
- From repo root: `flutter pub get` after pubspec changes, then `flutter analyze` (lint + typecheck), `flutter test`, `flutter build apk --release`. There is no separate lint/typecheck script.
- Focused tests (`flutter test <file> --plain-name "<name>"`): `floating_bubble_service_test.dart` / `recordWatchedVideo` and `history and reminder methods`; `widget_test.dart` / `background setting shortcuts open system settings`, `daily target drives progress`, `bottom navigation opens insights, history, and settings`; `onboarding_flow_test.dart` / `onboarding starts with notifications and keeps accessibility last`, `accessibility settings stay closed until restricted settings are confirmed`; `bubble_status_test.dart` / `tracking requires an active detector and a visible bubble`. The restricted-settings gate test currently asserts stale `Tap the three-dot menu` copy; source says `Look for Advanced settings`.
- Gradle redirects build output to repo-root `build/`; debug install loop: `flutter build apk --debug`, `adb install -r build\app\outputs\flutter-apk\app-debug.apk`. Release APK uses debug `signingConfig`; do not call it production-signed.

## App wiring / state
- `lib/main.dart` accepts optional service/storage; storage defaults to `SharedPreferencesOnboardingStorage`, service defaults downstream; gate is `onboarding_completed`; storage-load failure shows a retry screen. If service is null, `HomeScreen` and `OnboardingScreen` each build their own `FloatingBubbleService()` — inject one in `ReelCountApp` to share.
- Brand is Scrollo (`Scrollo: Reel Counter & Planner`) with bundled Inter font; `HomeScreen` is a bottom-nav shell (Home/Insights/History/Settings). It full-refreshes on init/resume (counter, status, daily target, history, reminder, pause status, confirmed steps, setup issues), but its event listener mirrors only counter/status; `_safeHistory`/`_safeReminder` swallow errors. Dashboard setup issues cover overlay/background/autoStart/pauseApp/accessibility only; `restrictedSettings` appears via `Setup & Permissions`.
- Onboarding keys `onboarding_completed`, `onboarding_step`, `onboarding_confirmed_steps` are Dart SharedPreferences, separate from native `reelcounter_bubble`. Seven active steps: notifications -> overlay -> background -> autoStart -> pauseApp -> restrictedSettings -> accessibility; enum also has confirmation/success. `restrictedSettings` is user-confirmed; its card shows `ADVANCED SETTINGS`, directs users to open App Info via Settings > Apps > Scrollo, look for Advanced settings, enable "Allow restricted settings", return, then enable Scrollo Detection; its "Open App Info Settings" button reuses `requestPauseAppActivity()` (no dedicated intent). `Open Accessibility Settings` redirects there until confirmed. Confirmation gates completion; saved `success` resumes at confirmation; `Setup & Permissions` reopens at confirmation.
- Sole Dart bridge is `lib/services/floating_bubble_service.dart`; Dart talks only to `FloatingBubbleChannel`. Native detection writes directly via `ReelDetectionAccessibilityService` -> `VideoCounterManager` -> `BubblePreferences` and notifies the channel. Bridge `recordWatchedVideo()` is a manual/test surface, not the production path.
- Fixed channels `com.reelcount.app/floating_bubble` and `com.reelcount.app/floating_bubble_events`; keep Dart `FloatingBubbleMethod`/`FloatingBubbleEventName`, Kotlin `FloatingBubbleChannel.Method`/`Event`, and tests in sync. No `updateCounter`/`incrementCounter`/`decrementCounter`. `ReelPlatform.fromKey`/`BubbleEventType.fromValue` use `firstWhere` with no `orElse`, so unknown keys throw `StateError` (events surface as `addError`).
- Status payload has current `detectionState/detectionMessage` plus legacy `trackingState/trackingMessage`, `trackingEngineConnected`, `trackingActive`; keep `BubbleStatus.fromMap` aliases; Dart `trackingEngineConnected` is an alias for `accessibilityServiceRunning`, while native computes them separately. `bubbleVisible` requires overlay permission + running service + persisted `bubble_active`; `expanded` requires visible; `trackingActive` requires detection `active` + visible.
- `sendEvent()` drops consecutive identical event-type+status signatures and never represents daily target. `onHostResumed()` emits only overlay/accessibility changes from attach-time baselines, so no first-resume/per-read event.
- No manual `+1`/`-1`; reset is bulk and confirmation-gated (native `resetCounts()` clears current-day counters only, despite settings copy claiming history is cleared). Expanded bubble only has Collapse/Hide.
- Counters, `daily_target`, `daily_history`, and reminder/notification-preference keys live in native prefs `reelcounter_bubble`; target defaults to `50` and is clamped `>= 0`. Rollover is lazy (`ensureToday()`): it archives nonzero prior-day counts, clears counts, `counter_total`, and `processed_event_ids`, but leaves bubble positions; `BubbleCounts.total` is derived. Stable IDs can be recordable again after rollover unless still in `recentKeys`.
- Daily reminders use native `AlarmManager` + `DailyReminderReceiver`/`DailyReminderBootReceiver`, request `POST_NOTIFICATIONS` through the bridge, and never change Android settings programmatically; copy must tell users to open Scrollo before scrolling. Notification prompt is one-shot via `notification_permission_requested`; later denial needs `openNotificationSettings`, and `requestNotificationPermission()` returns false immediately after launching the prompt.

## Android lifecycle / permissions
- Overlay needs `SYSTEM_ALERT_WINDOW` + Android 8/O runtime checks. Keep `foregroundServiceType="specialUse"`, subtype `floating_bubble_counter`, FGS permissions, and permission checks. `dispatch()` no-ops unless the service runs, so `refreshCounter()` drops updates while stopped; AppOps revocation and `onTaskRemoved()` (`stopWithTask="true"`) tear the bubble down. Restore only when `canDraw` and persisted `bubble_active`.
- `VideoCounterManager.appTaskActive` is in-memory, starts `false`, and is set by `MainActivity`/`ScrolloTaskMonitorService`; the persisted `app_task_active` preference is unused. The monitor is `START_NOT_STICKY`, so process death or swipe-away stops counting until the app is reopened, and detection errors stay hidden as `stopped` while the gate is false.
- Accessibility permission means this component is in `ENABLED_ACCESSIBILITY_SERVICES`, not global `ACCESSIBILITY_ENABLED`; `accessibilityServiceRunning` is in-memory `isConnected`, distinct from permission and `trackingEngineConnected`.
- Keep delayed `runDetect()` cancellable/serialized and lifecycle callbacks guarded; caught failures route through `reportError()` to detection error state. Accessibility config must keep `flagReportViewIds|flagIncludeNotImportantViews|flagRetrieveInteractiveWindows`, `canRetrieveWindowContent=true`, and window/content/click/scroll events; XML `notificationTimeout="200"` is framework coalescing, while app debounce is ~500ms for window/content/click and 0ms for scroll.
- Background Activity: `allowed|restricted|unknown` from PowerManager Doze whitelist; request order is ignore-battery request -> battery-optimization list -> app details. Auto Background Start is action-only (no status query): try brand-specific OEM components after resolving them, then app details/apps list; add new OEM packages to manifest `<queries>`. Pause App Activity If Unused: API 30+ `isAutoRevokeWhitelisted` maps to `disabled|enabled|unknown`, and the request only opens settings. Never change these settings programmatically.

## Detection / identity
- Supported packages: Instagram (`com.instagram.android`, `com.instagram.barcelona`), YouTube/YouTube Music, Facebook (`katana`, `android`, `lite`), exact TikTok `com.zhiliaoapp.musically` plus `com.tiktok.` prefix, and Snapchat; unsupported/package-less events are ignored. `sessionNonce` is regenerated on every service connection.
- For YouTube/Instagram/Facebook, scroll transitions bypass the `sessionActive || lastKey != null` gate and cancel pending ~500ms detects; general scroll threshold is 60 but YouTube is 1 with `effectiveMagnitude=1` fallback. YouTube scroll direction treats negative delta as `next`, positive as `previous`.
- Viewer detection is BFS over `AccessibilityNodeInfo`, bounded by `MAX_NODES=1500`/`MAX_DEPTH=20`. Direct viewer branches allow non-scrollable Snapchat (`opera_viewer`/`spotlight_container`), YouTube, Instagram, and Facebook nodes; candidates require 0.6 width/0.5 height (FB direct-viewer height 0.3); 0.8x0.3 only counts FB letterboxed media. Text hints gate `allowed` for YouTube/Instagram/Facebook only when no idHint; `feedGuard` rejects feed-like nodes when no hint and >3 media-like nodes.
- Prefer author/caption identity: captions/author-field tokens must pass `stableToken` rules (length 2..140, lowercase, strip digits, reject social stats and generic tokens such as `create a reel`); regex authors bypass that filter and cap at 48. Structural fallback uses <=8 sorted tokens plus class/id/childCount/coarse bounds. Stable `eventId` is `baseKey`; unstable IDs add `sessionNonce#transitionEpoch`; `recentKeys` (32) plus native `processed_event_ids` suppress revisits.
- `COUNTER_UPDATED` is logged inside `recordWatchedVideo()`, so it can precede `REEL_RECORDED`; duplicates still log `REEL_RECORDED` with `duplicate=true` but skip `COUNTER_UPDATED`. `BUBBLE_UPDATED` is not guaranteed if the bubble service is stopped. `TREE`/`SCROLLABLE` dumps happen only on `no-viewer-node`, rate-limited ~3s per platform; `TREE` emits up to 60 interesting lines when debuggable vs 20 otherwise, `SCROLLABLE` up to 25, plus summaries; `no-root-window` emits no dump.

## Testing / on-device
- Channel tests mock `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`; event tests use `MockStreamHandler`; widget tests inject storage and assert no `+1`/`-1`, reset confirmation, and independent statuses. `widget_test.dart`'s `EventEmittingService` bypasses the mock messenger by overriding methods directly.
- For real detection, use `adb logcat -c; adb logcat -s ReelDetection VideoCounterManager BubbleUpdate`; add `AccessibilityManagerService AndroidRuntime ActivityManager` for lifecycle. Expected stages while the bubble is running: `VIEWER_DETECTED` -> `VIDEO_CONTENT_IDENTIFIED` -> `DUPLICATE_CHECK` -> `REEL_RECORDED` -> `BUBBLE_UPDATED`. `dumpsys accessibility` distinguishes bound from crashed service; `uiautomator dump` is the reference for viewer nodes. Pass `-s <serial>` when more than one device is listed.
