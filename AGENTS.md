## Facts / commands
- Flutter package is `reelcount` (imports `package:reelcount/...`) but source folder is `reelcounter`; Android namespace/applicationId and channel prefix are `com.reelcount.app`.
- `README.md` is untouched Flutter template. No CI, custom task runner, custom codegen config, or repo-local OpenCode config; trust `pubspec.yaml`, Gradle, and source.
- From repo root: `flutter pub get` after pubspec changes, then `flutter analyze` (lint + typecheck), `flutter test`, `flutter build apk --release` (Dart SDK `^3.12.2`).
- Focused tests: `flutter test test/floating_bubble_service_test.dart --plain-name "recordWatchedVideo"`, `flutter test test/widget_test.dart --plain-name "background setting shortcuts open system settings"`, `flutter test test/widget_test.dart --plain-name "daily target drives progress"`, `flutter test test/onboarding_flow_test.dart --plain-name "onboarding starts with notifications and keeps accessibility last"`, `flutter test test/bubble_status_test.dart --plain-name "tracking requires an active detector and a visible bubble"`.
- Gradle redirects build output to repo-root `build/`; debug install loop: `flutter build apk --debug`, `adb install -r build\app\outputs\flutter-apk\app-debug.apk`. Release APK uses debug `signingConfig`; never call it production-signed.

## App wiring / invariants
- `lib/main.dart` accepts optional service/storage; storage defaults to SharedPreferences there, service defaults downstream; gates onboarding vs `HomeScreen` on `onboarding_completed`; storage-load failure shows a retry screen. Native owns counters/status; Dart mirrors them.
- `HomeScreen` full-refreshes on init/resume (counter, status, daily target, pause status, confirmed steps, setup issues); its event listener mirrors only counter/status, so events do not refresh daily target or setup-issue state.
- Onboarding lives in `lib/screens/onboarding_screen.dart` + `lib/services/onboarding_storage.dart`; keys `onboarding_completed`, `onboarding_step`, `onboarding_confirmed_steps` are Dart SharedPreferences, separate from native `reelcounter_bubble`. Six active steps: notifications (informational, no runtime request) -> overlay -> background -> autoStart -> pauseApp -> accessibility; enum also has confirmation/success. Confirmation gates completion; saved progress is clamped to the six active steps (saved `success` resumes at confirmation); `Setup & Permissions` reopens at confirmation.
- Sole Dart bridge: `lib/services/floating_bubble_service.dart`. Dart talks only to `FloatingBubbleChannel`; native detection records directly via `ReelDetectionAccessibilityService` -> `VideoCounterManager` -> `BubblePreferences` and notifies the channel. Bridge `recordWatchedVideo()` is a test/manual surface, not the production detection path.
- Fixed channels `com.reelcount.app/floating_bubble` and `com.reelcount.app/floating_bubble_events`; keep Dart `FloatingBubbleMethod`/`FloatingBubbleEventName`, Kotlin `FloatingBubbleChannel.Method`/`Event`, and tests in sync. No `updateCounter`/`incrementCounter`/`decrementCounter`.
- Status payload has current `detectionState/detectionMessage` plus legacy `trackingState/trackingMessage`, `trackingEngineConnected`, `trackingActive`; keep `BubbleStatus.fromMap` aliases. `bubbleVisible` requires overlay permission + running service + persisted `bubble_active`; `expanded` requires visible; `trackingActive` requires detection `active` + visible.
- `sendEvent()` drops consecutive identical event-type+status signatures; daily target is not represented. `onHostResumed()` emits only overlay/accessibility changes from attach-time baselines, so no first-resume/per-read event.
- No manual `+1`/`-1`; reset is bulk and confirmation-gated. Detection calls `VideoCounterManager.recordWatchedVideo(platformKey, eventId)`; bridge exposes `recordWatchedVideo(ReelPlatform, {eventId})` with keys `instagram|youtube|facebook|tiktok|snapchat`; native dedupes `eventId`. Expanded bubble only has Collapse/Hide.
- Counters and `daily_target` live in the same native prefs `reelcounter_bubble`; target defaults to `50` and is clamped `>= 0`. Date rollover clears counts, `counter_total`, and `processed_event_ids`; bubble positions persist; `BubbleCounts.total` is derived and `counter_total` is only a cache.
- Overlay needs `SYSTEM_ALERT_WINDOW` + Android 8/O runtime checks. Keep `foregroundServiceType="specialUse"`, subtype `floating_bubble_counter`, FGS permissions, and permission checks. `dispatch()` no-ops unless the service runs, so `refreshCounter()` drops updates while stopped; AppOps revocation and `onTaskRemoved()` (`stopWithTask="true"`) tear the bubble down. Restore only when `canDraw` and persisted `bubble_active`.
- Accessibility permission = this component in `ENABLED_ACCESSIBILITY_SERVICES`, not global `ACCESSIBILITY_ENABLED`; `accessibilityServiceRunning` is in-memory `isConnected`, distinct from permission and `trackingEngineConnected`.
- Keep delayed `runDetect()` cancellable/serialized and lifecycle callbacks guarded; caught failures route through `reportError()` to detection error state. For "Not working", use `dumpsys accessibility` (`Bound services` vs `Crashed services`); `SERVICE_CONNECTED` is the in-repo rebind marker.
- Accessibility config keeps `flagReportViewIds|flagIncludeNotImportantViews|flagRetrieveInteractiveWindows`, `canRetrieveWindowContent=true`, and window/content/click/scroll events. XML `notificationTimeout="200"` is framework coalescing; app debounces window/content/click ~500ms, scroll 0ms.
- Supported packages are Instagram, YouTube/YouTube Music, Facebook/Katana/Lite, TikTok prefixes, and Snapchat; unsupported/package-less events are ignored. `sessionNonce` is regenerated on every service connection.
- For YouTube/Instagram/Facebook, scroll transitions bypass the `sessionActive || lastKey != null` gate and cancel pending ~500ms detects; general scroll threshold is 60 but YouTube is 1 with `effectiveMagnitude=1` fallback when scroll delta is unavailable. YouTube scroll direction label treats negative delta as `next`, positive as `previous`.
- Viewer detection is BFS over `AccessibilityNodeInfo`, bounded by `MAX_NODES=1500`/`MAX_DEPTH=20`. Direct viewer branches allow non-scrollable Snapchat (`opera_viewer`/`spotlight_container`), YouTube, Instagram, and Facebook nodes; candidates require 0.6 width/0.5 height (FB direct 0.3, letterboxed 0.8x0.3). Text hints gate `allowed` for YouTube/Instagram/Facebook only when no idHint; `feedGuard` rejects feed-like nodes when no hint and >3 media-like nodes.
- Prefer author/caption identity: captions/author-field tokens must pass `stableToken` rules (length 2..140, lowercase, strip digits, reject social stats and generic tokens such as `create a reel`); regex authors bypass that filter and cap at 48. Structural fallback uses <=8 sorted tokens plus class/id/childCount/coarse bounds. Stable `eventId` is `baseKey`; unstable IDs add `sessionNonce#transitionEpoch`; `recentKeys` (32) plus native `processed_event_ids` can still suppress a detected revisit.

## Settings shortcuts (UI-only)
- Background Activity: `allowed|restricted|unknown` from PowerManager Doze whitelist; request tries ignore-battery settings, then app details. Keep `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`.
- Auto Background Start is action-only (`requestAutoBackgroundStart`): no status query; try brand-specific OEM components, resolve/check them first, swallow failures, then fall back to app details/apps list. Add new OEM packages to manifest `<queries>`.
- Pause App Activity If Unused: `checkPauseAppActivity` returns `disabled|enabled|unknown` from API 30+ `isAutoRevokeWhitelisted`; `requestPauseAppActivity` opens app details/apps list. Never change these settings programmatically; the user must do it manually.

## Live detection / tests
- Real detection is verified on-device: `adb logcat -c; adb logcat -s ReelDetection VideoCounterManager BubbleUpdate`; lifecycle adds `AccessibilityManagerService AndroidRuntime ActivityManager`. Stages: `VIEWER_DETECTED` -> `VIDEO_CONTENT_IDENTIFIED` -> `DUPLICATE_CHECK` -> `REEL_RECORDED` -> `BUBBLE_UPDATED`; runtime/security failures go through `reportError()` -> detection error state.
- `COUNTER_UPDATED` is logged inside `recordWatchedVideo()`, so it can precede `REEL_RECORDED`. `REEL_RECORDED` also logs SharedPreferences duplicates with `recorded`/`duplicate`; duplicates skip `COUNTER_UPDATED`.
- `TREE`/`SCROLLABLE` dumps happen only on `no-viewer-node`, rate-limited ~3s per platform; `TREE` emits 60 lines when debuggable (normally debug) vs 20 when non-debuggable (normally release), `SCROLLABLE` up to 25; `no-root-window` emits no dump.
- Local lab recipe (not repo-derived): with multiple adb devices use `-s 192.168.1.8:35183`. The Xiaomi test device blocks `adb shell input`/`keyevent` and `settings put secure`; user must scroll, toggle accessibility, and reproduce manually. After reinstall/`am force-stop`, re-toggle if the service does not rebind.
- `uiautomator dump` is the reference for viewer nodes. Channel tests mock `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger`; event tests use `MockStreamHandler`; widget tests inject storage and assert no `+1`/`-1`, reset confirmation dialog, and independent statuses. `widget_test.dart`'s `EventEmittingService` bypasses the mock messenger by overriding methods directly.
